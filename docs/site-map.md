## 二、首页 `/` 结构

从上到下 7 个区块。编号后面括号内是实现它的组件。

### 1. 顶部导航（`SiteHeader.astro`）
- 左：MakerX AI 标识（文字标 + 自绘 SVG 记号），点击回首页。
- 中/右：**实验项目**（锚点跳到 §4）、**我们的学习方式**（锚点跳到 §5）、**家长入口**（锚点跳到 §6）。
- 移动端：折叠为一个菜单按钮，展开为全屏列表；键盘可 Tab、可 Esc 关闭。
- 滚动时保持可用；不做遮挡内容的悬浮大块。
- **不出现**登录 / 报名 / 购物车等虚假入口。

### 2. Hero 首屏（`HeroLab.astro` + `HeroVisual.astro`）
- 品牌名：MakerX AI 造物实验室 —— **必须是真实 HTML 文本**，不能只存在于图片里。
- 主张（最大字号）：**把脑海里的想法，动手造出来。**
- 一句话介绍：从一个问题开始，借助 AI 设计、制作、测试，再把作品真正做出来。
- 主视觉：**使用用户提供的 `references/MakerX AI造物实验室.png`**（1774×887，作为完整视觉参考）。规格见 [visual-direction.md §五](visual-direction.md)。页面构图和动效可围绕它优化。
  - 实现组件名 `HeroVisual.astro`（原 `FloatingObject.astro` 仅在改用自绘备选方案时才需要）。
- **行动按钮只有一个**（决策 C-07）：
  - **主按钮**：「开始实验 001」→ 实验 001 页面。深墨 `#111315` 实心 + 白字。
  - **次行动**：「先看看怎么上课」→ §5 锚点。**渲染为文字链接，不是第二个实心按钮。**
  - 两者都必须真的能点，不出现伪按钮。
- 动效预算：入场 ≤ 1.2s 完成；之后只有主视觉**外层容器**做低强度漂浮（≤ 8px）；`prefers-reduced-motion` 下全部静态，且**品牌名与主张仍完整可读**。
- ⚠️ 待补：首屏图的 `alt` 文案（我未看过该图，无法撰写，见 [visual-direction.md §十一](visual-direction.md)）。

### 3. 造物流程（`CraftFlow.astro`）
五步横向流程：**想法 → 设计 → 与 AI 协作 → 测试与改进 → 展示**。
- 每步：序号 + 短标题 + 一句孩子能读懂的话。
- 桌面横向、移动端纵向堆叠；滚动进入时轻量揭示。
- 与实验 001 的课次步骤呼应（不复制课件原文，讲的是同一套方法）。

### 4. 项目实验区（`ProjectGrid.astro` → `ProjectCard.astro`）
- **实验 001** 卡片：主卡，占据最大视觉权重。
  - 卡片元信息采用「编号 + 名称 + 时长 + 状态」四段式（借鉴参考站 `类型 + 名称 + 年份` 的档案式条目，但字段按本项目重写）。
  - 例：`实验编号 001` / **我的 AI 小基地** / `2 课时 · 90 分钟/课时` / **`研发中`**
  - ⚠️ 状态为 **`研发中`（`status: "developing"`）**，不是「开放中」—— 第 2 节课内容、使用工具与可公开物料都还没确认（决策 C-08）。
  - 一句项目任务：把自己的想法变成个人网页，并在第二阶段改进它。
  - **该卡仍可点击**（`pageState: "live"`，页面已实现），但徽标如实显示「研发中」。
  - 主 CTA：进入实验 001。
- **未来项目卡（2–3 张）**：标注 `planned`，**只写编号占位与一句方向说明，不编造课时、目标、物料**。
- 卡片由**两个字段**驱动，不要混为一个（决策 C-08 / C-09）：
  - `status`（`developing` / `open` / `planned`）→ 决定**徽标文案与配色**。
  - `pageState`（`live` / `coming-soon`）→ 决定**是否渲染为可点的 `<a>`、是否显示箭头**。`coming-soon` 用虚线边框、不显示箭头、整卡为 `<div>`。
  - 两者组合都要能读，且都能用键盘操作（`live` 时）。

### 5. 为什么这样学（`LearningWhy.astro`）
- 4 条主张，每条「孩子做什么 → 因此学到什么」：
  1. 不是让 AI 替你做完 → 你要先把想法写清楚
  2. 不是一次就对 → 看结果、找问题、再改一版
  3. 不是只有成品 → 能解释自己为什么这样选
  4. 不是一个人做 → 把作品讲给别人听
- 排版以文字为主，允许一个轻量装饰元素，不做轮播。

### 6. 给家长的简短说明（`ForParents.astro`）
- 每个项目都有：学习目标、过程记录、可展示成果。
- 两次课的进阶关系：第 1 次做出来 → 第 2 次改好并讲出来。
- 隐私承诺：**不收集、不公开孩子的真实姓名、学校、照片等个人信息；示例一律使用代号。**
- 语气：陈述事实，不做焦虑营销、不做倒计时、不做「别人家孩子」。
- 联系方式区：**只有拿到真实信息才填**，否则显示「联系方式待补充」。

### 7. 页脚（`SiteFooter.astro`）
- 品牌标识 + 主张短句。
- 项目导航：实验 001（+ 未来实验占位）。
- 隐私说明（简短、真实）。
- 联系方式占位（同上）。
- 一行状态信息：`内容最后更新：YYYY-MM-DD`。**由内容文件的 `updated` 字段生成**；该字段**可选**，缺失时**整行不渲染**（而不是显示「待确认」），也不写死未来日期（决策 C-06）。

## 三、实验 001 详情页 `/lab/001-my-ai-base/`

模板 `ProjectLayout.astro` + 内容文件 `001-my-ai-base.md`。区块顺序对应用户的任务动线：**知道做什么 → 知道为什么 → 开始做 → 做得对 → 讲出来**。

### 0. 面包屑 + 项目头（`ProjectHeader.astro`）
- `实验编号 001` 标签、项目名 **我的 AI 小基地**、副标题「用 AI 把一个想法变成可打开、可继续改进的个人网页」。
- 元信息条：适龄 9–12 岁 · 每班 5 人 · 2 课时 × 90 分钟 · 状态。
- 锚点快捷条（sticky，移动端横向滚动）：目标 / 准备 / 步骤 / 提示词 / 物料 / 验收 / 路演。

### 1. 项目任务（`ProjectMission.astro`）
- 一段话任务书 + 「最后你会拿到什么」清单：一个能双击打开的网页文件、填好的《内容工作纸》与《网站提示词》、一段 3 分钟讲解。
- ⚠️ **不得写出具体的模块数量。** 工作纸列 5 站、提示词模板给 3 个空位、PPT 收尾说「4 个模块到位」，三处不一致（决策 D-02）。定义统一前，此处只写「你的网站模块」。
- 页面可显式展示 `openQuestions[]` 里的未确认事项（如「模块数量待确认」），把不确定性摆在明面上而不是藏起来。

### 2. 学习目标（`LearningGoals.astro`）
- 六项能力（来自任务书）：需求表达、提示词结构、AI 输出判断、网页内容/风格/布局、测试与迭代、口头表达。
- 每项写成三段：**孩子版一句话**（我能做到…）+ **老师看什么**（证据）+ **怎么算做到**。
- 不写「培养创新思维」这类无法验收的空话。

### 3. 课前准备（`PrepChecklist.astro`）
- 设备：可联网笔记本、浏览器、能保存文件的目录。
- 工具：由内容文件声明（**待确认，见产品简报 §8**）。未确认前只写类别，不写具体产品名，避免误导。
- 安全与边界：不填真实姓名/学校/住址/电话；不使用真实照片；只在老师指定的位置保存文件。

### 4. 实验步骤（`StepList.astro`）
- 按课次分组：**课次 01**（做出 1.0）与 **课次 02**（改成 2.0 并路演）。
- 每步字段：序号、标题、时长（分钟）、做什么（动作句）、产出物、老师提示。
- 步骤内容严格来自 PPT 与两份工作纸，例如：
  - 课次 01：同题不同画体验 → 得到「AI 不会读心术」的结论 → 认识个人网站与版本迭代 → 定模块/风格/布局三个决定 → 填《内容工作纸》（10 分钟）→ 按七段模板写提示词 → 生成并保存文件 → 双击打开检查。
  - 边界写进步骤：「今天先不做：动画、音乐、多个页面、点赞」。
- ⚠️ **课次 02 的教案目前不存在**（已确认仓库与本机均无该文件）。因此课次 02 只渲染**已确认的意图**（「把小基地填满、变好看」+「站上台，讲给爸爸妈妈听」），步骤区显示「待确认」。
  **严禁**由模型补一段看起来合理的第 2 节课流程 —— 那是「不生成虚假课程文件」这条硬约束最容易被违反的地方（决策 D-03 连带）。
- 每步可勾选完成（本地状态，**不联网、不存储个人数据**；用 `sessionStorage`/内存即可，刷新丢失可接受）。

### 5. 提示词工具箱（`PromptBox.astro`）
- 卡片式：每条含 **什么场景用** + **可复制提示词正文** + **怎么改**（把哪些地方换成自己的词）。
- 首批内容：
  1. 《网站提示词》七段式总模板（名称 / 我是谁 / 头像 / 模块 / 风格 / 主色 / 布局）。
  2. 示例提示词（PPT 原例：角色设定「顶级科技极客」、主题「我的火星生存基地」、颜色「深空黑和荧光绿」、第一模块「超酷炫的太空站自我介绍」）——作为**范例**展示，明确标注是示例不是答案。
  3. 「把话说清楚」改写对照（模糊 → 具体），承接「AI 不会读心术」。
- 复制按钮：`navigator.clipboard` 成功/失败都要有可读反馈（失败时提示手动选中）。
- 提示词正文用代码块呈现：等宽字体、可横向滚动、不被装饰覆盖。

### 6. 素材与下载（`ResourceList.astro`）
- 严格两类状态：
  - `ready`：**文件已确认存在且允许公开**，才渲染真实链接与文件名。
  - `pending`：显示「待补充」+ 说明这份材料将来是什么，**不生成链接**。
- ⚠️ **第一版没有登录系统 → 发布出去的页面与静态文件任何人可访问。** 因此 `ready` 的前提不只是「文件在仓库里」，还包括**「已确认可以公开」**。未获授权前，教师自制的 PPT 与工作纸一律保持 `pending`（决策 D-04）。
- 预计条目：《内容工作纸》、《网站提示词》、空白规划表、提示词卡、验收清单、第 1 节 PPT（**公开与否待确认，目前全部 `pending`**）。
- 字段用 `path`（不是 `href`）；`state: "ready"` 必须同时有 `path` 与非空 `license`，由**构建前检查脚本**验证文件真实存在（`scripts/check-resources.mjs`，见 [content-model.md §4.2](content-model.md)）—— schema 本身看不到磁盘，**不能只靠 Zod**。
- 这条规则写进组件注释，防止后续误加假链接。

### 7. 作品验收标准（`RubricTable.astro`）
- 维度：内容、风格、布局、可用性、**能否解释自己的决定**。
- 每维度三档：`起步` / `不错` / `很棒`，用孩子能读懂的话描述。
- 至少一条面向「过程证据」：能说出改过什么、为什么改。
- 表格在移动端转为卡片列表，不横向溢出。

### 8. 路演指南（`PitchGuide.astro`）
- 3 分钟结构：我是谁 → 我的小基地是做什么的 → 我做的三个决定（模块/风格/布局）及原因 → 下一版想改什么。
- 展示清单：能双击打开、能翻到要点、能回答一个问题。
- 承接 PPT 收尾页「站上台，讲给爸爸妈妈听」。

### 9. 作品集出口（`PortfolioExit.astro`）
- 说明这个作品以后会整理进孩子自己的数字作品集，以及下一步会做什么。
- **明确写出**：现在还没有公开上传/展示功能；这是刻意的产品决定，不是缺陷。

### 10. 上一实验 / 下一实验（`ProjectNav.astro`）
- 由内容文件的 `order` 自动计算相邻项目；只有一个项目时**整块隐藏**，不显示死链接。

## 四、移动端与降级策略（跨页面）

| 情况 | 处理 |
|---|---|
| 窄屏（< 768px） | 导航折叠为菜单；**首屏图缩到约 45% 宽并移到文字下方**（保持 2:1，不裁切）；流程改纵向；锚点条横向滚动 |
| 触屏 | 所有 hover 效果必须有等价的可聚焦/可点击状态；不依赖光标跟随 |
| `prefers-reduced-motion: reduce` | 关闭漂浮、视差、滚动揭示与描边动画；元素直接处于最终状态（参考站 haoqi.design 的做法：SVG 描边直接 `stroke-dashoffset: 0; opacity: 1`） |
| 无 JS | 内容必须完整可读可导航；复制按钮降级为可手动选中的文本；勾选状态丢失可接受 |
| 打印（老师可能打印步骤） | 步骤区与验收表可打印，隐藏装饰、导航与首屏图（省墨） |

⚠️ **首屏图在窄屏上会变得很矮**（2:1 比例）。因此**品牌名与主张必须以真实 HTML 文本存在**，不能让它们只出现在图片里 —— 否则小屏上品牌信息会缩到不可读。

## 五、组件清单（第一版）

**布局**：`BaseLayout`、`ProjectLayout`
**导航**：`SiteHeader`、`SiteFooter`、`ProjectNav`、`AnchorNav`
**首页**：`HeroLab`、`HeroVisual`（承载用户提供的首屏图）、`CraftFlow`、`ProjectGrid`、`ProjectCard`、`LearningWhy`、`ForParents`

**刻意不建的组件**：轮播、弹窗广告、登录框、表单提交、评论区、上传控件。
