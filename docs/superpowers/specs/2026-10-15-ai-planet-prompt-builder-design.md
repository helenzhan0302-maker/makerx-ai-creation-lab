# AI星球课堂建站提示词工具设计

> 状态：方案已在对话中逐项确认，本文用于实现前的最终书面审核。
> 日期：2026-10-15
> 范围：实验 001「AI星球」项目页内的静态课堂填写工具

## 一、目标与边界

### 目标

- 让 9–12 岁孩子在课堂中，不填写姓名等敏感信息，也能一步一步完成个人网站构思。
- 将固定选择变成中文卡片，将无法预设的内容保留为中文输入框。
- 生成一段完整、清晰、可复制的中文建站提示词。
- 让每个浏览器会话只保留自己的填写状态，适合腾讯云上的静态部署。
- 保持与 MakerX 现有首页的视觉语言一致：轻盈浅色底、深墨文字、青蓝装饰、克制动效。

### 不做

- 不收集孩子姓名、学校、班级、联系方式、照片或其他真实身份信息。
- 不使用数据库、登录、接口、云函数、统计、广告或第三方表单。
- 不写入 `localStorage`、`sessionStorage` 或 Cookie；刷新/关闭页面后内容清空。
- 不自动调用 AI，不把填写内容上传到服务器。
- 不直接使用受版权保护的 IP 角色图片、字体、插画或品牌资产；头像使用原创类型卡片，可自绘或文字化表现。
- 不在本次功能中扩展完整课程管理、作品上传或在线保存。

## 二、页面入口与用户流程

### 入口

- 首页项目档案中的第一个项目名称改为「AI星球」。
- 项目卡片可点击，进入项目页；项目页内展示课堂填写工具。
- 新页面使用项目专属标题「AI星球」，不再对外显示「AI 小基地」。原始课件和工作纸中的旧标题仅作为历史素材名称保留，未确认公开授权前不渲染下载链接。

### 混合式填写流程

整体采用「一步一项 + 最后汇总」：

1. 网站名字
2. 头像 / 形象
3. 介绍自己
4. 网站要放的内容
5. 网站风格
6. 主色与搭配色
7. 页面布局
8. 检查并生成中文提示词

每一步只处理一个主题。顶部显示当前进度，提供「上一步」与「下一步」。最后的检查页汇总已填写内容，允许返回任意步骤修改。

### 字段规则

| 步骤 | 字段 | 交互 | 必填 |
|---|---|---|---|
| 1 | 网站名字 | 中文文本输入 | 是 |
| 2 | 头像 / 形象 | 卡片最多选 2 个；也可使用自定义描述 | 是，卡片或描述至少一种 |
| 3 | 介绍自己 | 一句话介绍、最喜欢的内容、希望别人知道的内容，三个中文输入框 | 否 |
| 4 | 网站内容 | 中文卡片多选 + 自定义补充输入 | 是，至少一个卡片或自定义内容 |
| 5 | 网站风格 | 中文卡片单选 | 是 |
| 6 | 颜色 | 中文色卡最多选 3 个 + 自定义颜色输入 | 是，至少一种颜色 |
| 7 | 页面布局 | 中文卡片单选 | 是 |

核心必填字段未完成时，不能进入检查/生成；当前步骤直接显示中文提示，不依赖弹窗。可选的自我介绍字段为空时，生成结果中省略对应句子。

## 三、选项内容

### 头像 / 形象卡片

卡片采用原创、可自绘的形象类型，不引用具体 IP：

- 像素建造师
- 机器人发明家
- 恐龙探险家
- 太空旅行者
- 怪兽训练家
- 魔法学徒
- 原创超级英雄
- 机甲驾驶员
- 忍者探险家
- 海底探险家
- 赛车手
- 猫咪伙伴
- 狗狗伙伴
- 兔子伙伴
- 自然精灵
- 自己描述

“自己描述”使用中文输入框；选择卡片后仍可补充细节。超过两个头像时，第三个卡片不可选并给出中文提示。

### 网站内容卡片

采用多选卡片，不设置固定的模块数量，避免与历史课程材料中不一致的数量产生冲突。选项包含：

- 关于我
- 我的爱好
- 我的作品
- 我的梦想
- 我的收藏
- 我的宠物
- 我的游戏世界
- 我的小发明
- 我的旅行地图
- 我推荐的书或电影

保留“自己补充”输入框。页面不声称固定的模块数量，生成提示词只列出孩子实际选中的内容。

### 风格卡片

单选，使用已确认的中文选项：

- 活泼热闹
- 安静干净
- 科技酷炫
- 自然清爽
- 梦幻想象

### 颜色卡片

最多选择 3 个，按选择顺序生成“主色 / 搭配色”。中文选项为：天空蓝、海洋蓝、薄荷绿、草地绿、柠檬黄、橘子橙、草莓红、葡萄紫、樱花粉、深空黑、奶油白、彩虹渐变；另有“自己填写颜色”。

### 布局卡片

单选，沿用课堂工作纸中的中文表达：

- 竖着一路排
- 左右分开
- 中间开花
- 格子铺开
- 左右交替走

## 四、生成结果

生成结果页只承担一件事：展示一段完整的中文提示词。提示词使用固定的中文结构，并把用户输入安全地转义后插入文本，不执行用户输入中的 HTML 或脚本。

结构如下：

```text
你是一位经验丰富的网站设计专家，特别擅长帮小学生做出好看又好用的个人网站。
请帮我做一个【个人网站】。下面是我的想法：

一、网站名称：……
二、我的头像 / 形象：……
三、我想这样介绍自己：……
四、网站上要放的内容：……
五、整体风格：……
六、主色与搭配色：……
七、页面布局：……
```

空白的自我介绍字段不输出空行；多选内容、头像和颜色以中文顿号或换行整理。结果区域使用可选中的普通文本，不依赖复制 API 才能阅读。

结果页提供：

- 「复制提示词」：优先使用 `navigator.clipboard.writeText`。
- 复制失败时保留文本可手动选择，并显示“复制没有成功，请长按或拖动选中文字复制”。
- 复制成功显示“已复制，可以交给 AI 制作网站啦！”。
- 「返回修改」：回到汇总页，不清空当前内存状态。

## 五、运行时数据与隐私隔离

使用单页内存对象保存当前填写状态。所有数据只在当前页面的 JavaScript 运行时存在，不写浏览器存储，不发送网络请求。静态服务器只返回 HTML、CSS、JavaScript 和静态资源，不持有任何孩子填写的内容。

因此，5–10 个浏览器或设备同时访问时，每个页面拥有独立的内存对象，不会共享状态；一个孩子修改、刷新或关闭页面不会影响其他页面。刷新或关闭后状态清空是预期行为。

## 六、实现边界与组件职责

- `src/pages/index.astro`：把项目卡片名称改为「AI星球」，并链接到项目页。
- `src/pages/lab/001-ai-planet.astro`：项目页结构、无 JS 时的基本可读内容、工具入口。
- `src/components/ProjectPromptBuilder.astro`：表单结构、步骤容器、进度、汇总和结果区；不直接硬编码大段选项文案。
- `src/lib/ai-planet-builder.ts`：选项定义、状态类型、必填校验、提示词生成纯函数；不产生副作用。
- `src/styles/ai-planet-builder.css`：卡片、步骤、结果区域、移动端和降级样式。
- `src/content/projects/001-ai-base.md` 或对应的新项目内容文件：项目展示标题与说明的内容来源；是否重命名文件由实现时按现有路由兼容性决定，不能留下死链。

页面脚本只负责把 DOM 事件连接到纯函数，禁止调用数据库、网络 API 或浏览器持久化 API。

## 七、可访问性、响应式与动效

- 使用原生 `form`、`fieldset`、`legend`、`label`、`button` 和可聚焦卡片；卡片选择不只依赖鼠标。
- 所有按钮、输入框和选项使用中文可读名称，键盘焦点清晰可见。
- 手机端单列显示，卡片有足够点击区域；结果提示词不横向溢出。
- 当前步骤和错误提示使用 `aria-live` 或等价语义传达。
- 动效只用于步骤切换、进度和轻微卡片反馈；内容不等待动画出现。
- `prefers-reduced-motion: reduce` 下关闭步骤动画和装饰动画，所有内容直接可见。
- 无 JavaScript 时，页面仍能读到项目说明和填写字段；生成按钮不可用时不伪造成功状态，提示用户启用脚本完成组合。

## 八、错误处理与验证

### 交互校验

- 网站名字为空：提示“请先写一个网站名字”。
- 头像既未选卡片又未填写描述：提示“请选择一个形象，或写下你自己的想法”。
- 网站内容为空：提示“至少选择一项内容，或自己补充一项”。
- 风格、颜色或布局为空：提示对应的中文选择提醒。
- 头像超过两个或颜色超过三个：阻止超额选择并提示限制。
- 复制 API 不可用或失败：不丢失提示词，给出手动复制提示。

### 自动化验证

- 纯函数测试：必填校验、头像/颜色上限、空字段省略、中文提示词生成、特殊字符作为文本处理。
- 页面测试：项目名称为 AI星球、项目卡片可进入项目页、步骤可前进/后退、汇总可返回修改、生成区可见。
- 构建验证：`pnpm check`、`pnpm build`、`pnpm test`。
- 浏览器验证：桌面和窄屏无横向溢出；键盘可完成选择和生成；复制成功/失败反馈可见；`prefers-reduced-motion` 下内容静态完整；至少打开两个页面确认状态不互相污染。

## 九、验收标准

- 首页第一个项目显示为「AI星球」，点击后进入工具页。
- 不出现孩子姓名字段，也不出现任何上传或保存入口。
- 固定内容均为中文卡片；开放内容均有中文输入框。
- 头像最多两个，颜色最多三个，规则在界面中可理解。
- 只有核心字段完成后才能生成；可选自我介绍为空时不产生多余空白。
- 生成结果只是一段可复制的中文提示词，不自动上传、不调用 AI。
- 刷新页面后内容消失；两个页面的状态互不影响。
- 无死链、无控制台错误、无构建错误、无横向溢出。
