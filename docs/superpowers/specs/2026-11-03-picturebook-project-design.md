## 一、先说结论

网站不替孩子写故事，也不做“聊天框里的 AI 代写”。网站承担四件课堂里最容易丢失的事：

1. **问**：用苏格拉底式追问，每次只问一个关键问题。
2. **记**：把孩子自己说出的答案留在故事卡里，跨两节课不丢。
3. **生成**：把已经确认的内容整理成可复制的分镜提示词、插画提示词和修改提示词。
4. **查**：把 PPT 的验收标准变成孩子能自己勾选的检查单。

两节课共用一个「故事卡」，而不是两个互不相干的生成器：

```
故事卡（主角 / 目标 / 困难 / 行动 / 结果）
   ↓ 第 1 节课后半段
分镜卡（逐页：画面 / 动作 / 情绪）
   ↓ 第 2 节课
绘本卡（逐页：提示词 / 选图状态 / 检查结果）
   ↓ 首映礼
路演卡（故事讲什么 / 最满意的一页 / 下一步想改什么）
```

**没有故事卡，就不生成分镜；没有分镜卡，就不生成插画。** 这条依赖关系是本规格的核心，不允许用“一键生成全部”绕过。

### 2.3 本规格采用的关键口径

1. **实验编号与名称**：使用 `002`，对外名「故事放映机」，路由 `/lab/002-picturebook/`。
2. **产物页数**：**固定 6 页**。分镜与插画都以 6 页为单位；提示词模板读取同一份配置，不在组件里散落数字。
3. **苏格拉底式追问的边界**：AI 每轮最多问一个问题，只做澄清与追问，不提供“完整故事答案”，不替孩子决定情节。

5. **版本管理教学**：导出文件名固定包含项目代号、课次与版本号，例如 `story-project-v1.json` → `story-project-v2.json`。网站不删除旧文件，只提示孩子“保留上一版，不要覆盖”。

## 四、核心交互：苏格拉底式多轮追问

### 4.1 设计原则

这不是“AI 聊天机器人”，而是一个**有终止条件的提问流程**。每一轮只做四件事：

1. 复述孩子上一轮说出的关键内容，确认没有曲解。
2. 指出一个仍然模糊的地方。
3. 只问一个问题。
4. 给一个可跳过、可编辑的示例方向，不直接给完整答案。

禁止行为：

- 一次问多个问题。
- 替孩子补写完整情节。
- 评价“这个想法好不好”。
- 把“AI 觉得更好”的版本设为默认。
- 在孩子没有回答时自动推进。

### 4.2 五要素的追问顺序

顺序不是固定问卷，而是**依赖驱动**：前一个要素没有足够具体的信息，后一个要素的追问就没有意义。

| 阶段 | 要素 | 进入条件 | 追问目标 | 完成条件（可检查） |
|---|---|---|---|---|
| S1 | 主角 | 孩子选了一个起点 | 主角是谁、想要什么、有什么特点 | 能用一句话说出「谁 + 想要什么」 |
| S2 | 目标 | 主角已明确 | 目标是否具体、是否可被读者看见 | 目标是一个可观察的结果，不是“变好”这类空词 |
| S3 | 困难 | 目标已明确 | 谁/什么阻止了主角，为什么不容易 | 困难与目标直接冲突 |
| S4 | 行动 | 困难已明确 | 主角具体做了什么，而不是“努力了” | 至少一个可画出来的动作 |
| S5 | 结果 | 行动已明确 | 最后发生了什么变化，主角或世界有何不同 | 结果回应目标，且不是“然后就好了” |

### 4.3 单轮状态机

```
idle
  → ask（只输出一个问题 + 一个可跳过示例）
  → wait_for_child（孩子输入或选择“我不知道”）
  → reflect（复述孩子答案，标出仍模糊处）
  → check（是否达到该要素的完成条件）
      ├─ 否 → ask（换一个更小的问题，最多 3 次）
      └─ 是 → confirm（显示孩子原话 + 可编辑摘要）
          → next_element
```

**最多追问 3 次**。3 次后仍答不出，不逼问，改为：

> “先留一个空格也可以。你可以选一个方向，之后随时回来改。”

并提供 2–3 个**方向选项**（不是完整情节），例如“把困难变大 / 把目标变具体 / 换一个主角最在意的东西”。

### 4.4 每轮的输出格式

工具生成给孩子看的内容必须固定为四段，顺序不能变：

```text
我听到的是：<复述孩子上一轮的原话要点>
还想确认：<一个具体的模糊点>
下一个问题：<只问一个问题>
如果暂时想不到，可以从这里选一个方向：<2–3 个短方向，可跳过>
```

不输出“建议你这样写：……”的完整段落。

### 4.5 提问质量规则（实现时要可测试）

1. 每个问题只能有一个问号。
2. 问题中不得出现“你应该”“最好”“正确写法”等指令性词。
3. 问题必须指向可观察的细节：谁、在哪里、做了什么、发生了什么变化。
4. 不得问孩子个人信息（真实姓名、学校、住址、电话、照片）。
5. 不得要求孩子描述真实同学、老师或家人的可识别信息。
6. 孩子说“不知道”时，不重复同一个问题，改用更小的二选一或方向选项。
7. 每轮复述必须引用孩子自己用过的词，不能替换成成人化表达。
8. 达到完成条件后立即停止追问，进入确认，不“顺便多问一个”。

### 4.6 提示词如何引导孩子持续对话

网站不把“苏格拉底式提问”四个字直接丢给孩子。孩子看到的是按钮与问题；真正发给 AI 的是一段**角色约束 + 当前故事卡 + 下一步只问一个问题**的提示词。

基础提示词骨架：

```text
你是我的故事搭档，不是代写者。
你的任务：帮我把故事想清楚，但故事由我决定。

规则：
1. 每次只问我一个问题，等我回答后再问下一个。
2. 先复述你听到的我的原话，再指出一个还不清楚的地方。
3. 不要替我写完整情节，不要替我决定结局。
4. 不要评价我的想法好不好，只帮我把它说得更具体。
5. 如果我说“不知道”，给我两三个方向让我选，不要逼我。
6. 不要问我真实姓名、学校、住址、电话或照片。

现在我的故事卡是：
主角：<孩子原话或“还没想好”>
目标：<...>
困难：<...>
行动：<...>
结果：<...>

请从「<当前要素>」开始，只问我一个问题。
```

下一轮时，把孩子的回答追加到故事卡，并把“当前要素”推进到下一个未完成的格子。**每轮都重新发送完整故事卡**，避免多轮后 AI 忘记前文。

### 4.7 终止与回退

- 孩子可随时点「这句不是我想要的」→ 回到上一轮，保留原答案，不覆盖。
- 孩子可随时点「先跳过」→ 该格标记「待补充」，不阻塞后面的探索，但在生成分镜前必须提示未完成项。
- 五要素全部确认后，显示「故事卡完成」而不是「故事完成」，避免暗示作品已经结束。
- 每格保留「孩子原话」与「整理后的句子」两个版本；生成提示词时默认用孩子原话，整理版只作参考。

## 五、两节课的网站配合节奏

### 5.1 第 1 节课：故事 → 分镜

| 课堂阶段 | 网站承担 | 孩子产出 | 老师能看到 |
|---|---|---|---|
| 故事起点 | 三选一起点卡 | 一个起点 | 谁还没开始 |
| 五要素追问 | 逐项提问、复述、确认 | 故事卡五格 | 哪一格反复说不清 |
| 故事自检 | 三问：这是我想讲的吗、最满意哪里、改过什么 | 一句自评 | 孩子是否能解释自己的选择 |
| 拆分页数 | 固定 6 页 | 6 页分镜卡 | 是否每页都有任务 |
| 分镜填写 | 每页三格：画面 / 动作 / 情绪 | 分镜卡 | 哪页只有“发生了一件事” |
| 生成分镜提示词 | 汇总孩子原话 | 可复制文本 | 提示词是否包含五要素 |

第 1 节课**不生成插画**，也不出现画风选项。避免孩子跳过分镜直接追求“好看的图”。

### 5.2 第 2 节课：分镜 → 绘本

| 课堂阶段 | 网站承担 | 孩子产出 | 老师能看到 |
|---|---|---|---|
| 回看故事卡 | 导入第 1 节工程文件并显示 | 确认或修改 | 是否找回了自己的故事 |
| 画风设定 | 比例 / 画风 / 色调三组单选 | 画风卡 | 是否三项都选了 |
| 角色固定特征 | 四项输入：颜色、发型/外形、衣服、标志物 | 角色卡 | 是否具体到可复现 |
| 主角参考图 | 生成第一段提示词 | 一张参考图（站外生成） | 是否先确认长相再批量生成 |
| 逐页插画 | 每页一段提示词 + 检查项 | 每页提示词与选图状态 | 是否逐页检查而不是只看漂亮 |
| 出厂检查 | 四项勾选 | 检查单 | 是否发现页序或一致性问题 |
| 首映礼 | 三问路演卡 + 同伴反馈句式 | 口头表达 | 能否说清故事与修改理由 |

### 5.3 跨周数据流：本地工程文件

用户已确认两节课分两个周六上，且接受孩子把第 1 节产物保存到自己的电脑。**浏览器存储不做**：教室电脑可能多人共用，`localStorage` 既无法可靠区分孩子，也会把儿童创作内容留在设备上。

| 环节 | 做法 | 为什么 |
|---|---|---|
| 第 1 节结束 | 点「保存工程文件」，下载 `story-project-v1.json` | 文件归孩子本人，站点不保存 |
| 课后 | 孩子把文件放进自己的课程文件夹；老师教一句“不要删除上一版” | 建立最基本的版本管理习惯 |
| 第 2 节开始 | 点「打开我的工程」，选择该 `.json` 文件 | 跨电脑、跨周恢复，不依赖浏览器 |
| 第 2 节结束 | 再导出 `story-project-v2.json`，保留 v1 | 能对比“改过什么、为什么” |
| 文件丢失 | 页面提供「从空白开始」和「手动填写故事卡」两条路 | 不让孩子因丢文件无法上课 |

**工程文件格式**

- 单一 `.json` 文件，顶层字段固定为：

```json
{
  "schemaVersion": 1,
  "projectCode": "002-picturebook",
  "exportedAt": "2026-11-07T10:30:00+08:00",
  "version": 1,
  "story": {
    "start": "wish",
    "hero": "",
    "goal": "",
    "obstacle": "",
    "action": "",
    "result": ""
  },
  "storyboard": [
    { "page": 1, "scene": "", "action": "", "emotion": "" }
  ],
  "visual": {
    "ratio": "",
    "artStyle": "",
    "palette": "",
    "traits": { "color": "", "shape": "", "clothes": "", "mark": "" }
  },
  "checks": {
    "storyUnderstandable": false,
    "pageOrderClear": false,
    "imagesMatchPlot": false,
    "characterConsistent": false
  }
}
```

- `storyboard` 必须正好 6 项，`page` 为 1–6 且不重复；导入时缺页或重页直接拒绝，不自动补空页。
- 只含故事卡、6 页分镜、画风与角色设定、检查状态；**不含姓名、学校、照片、联系方式**。
- 导入时只读取上述已知字段；未知字段忽略，**不执行**其中的 HTML 或脚本；字符串统一按纯文本渲染。
- 导入失败必须给出可读原因：`不是工程文件` / `工程文件版本过新` / `分镜缺页` / `分镜页序重复` / `文件内容不完整`。
- 每次导入后先显示「找到第 N 版，包含 6 页分镜」，由孩子确认后再覆盖当前内容；不静默替换。
- 文件名由工具生成：`story-project-v1.json`、`story-project-v2.json`……。孩子不需要自己拼版本号，页面同时显示「这是第 2 版」。

**版本管理怎么教（儿童版，控制在 3 句话内）**

1. **保存 = 留一份。** 下课时点一次「保存工程文件」，就像把画放进文件夹。
2. **改之前先留旧版。** 不要覆盖 `v1`，让它和 `v2` 同时存在；旧版是“反悔按钮”。
3. **文件名就是时间线。** `v1` 是第一次，`v2` 是第二次；数字越大越新，不是越大越好。

课堂动作：第 1 节结束统一导出 `v1`；第 2 节开始先导入 `v1`；第 2 节改完后导出 `v2`，并把两个文件并排放一次，让孩子指出“哪一版变了、为什么”。

**这不是用户数据隔离。** 站点是静态站，没有账号体系，也没有服务器端数据。所谓隔离只发生在“每个孩子自己的电脑文件”这一层：共用电脑时，后一个孩子看不到前一个孩子的文件，除非前一个孩子把文件留在桌面。老师需要口头要求孩子下课后把文件带走或放进个人目录。

## 六、提示词设计

所有提示词都满足三条：**可复制、可编辑、可检查**。不使用“一键生成完整绘本”的提示词。

### 6.1 故事追问提示词（第 1 节，逐轮）

见 §4.6。每轮只推进一个要素，且把完整故事卡带回给 AI。

### 6.2 分镜提示词（第 1 节末）

```text
请根据我的故事卡，帮我把故事拆成分镜。
不要新增我没有说过的主要情节，不要替我改结局。

我的故事卡：
主角：<...>
目标：<...>
困难：<...>
行动：<...>
结果：<...>

请按 6 页输出，每页只写三项：
1. 画面发生什么
2. 角色在做什么
3. 角色是什么情绪

如果某一页信息不够，先问我一个问题，不要自己补。
```

> 6 页是对外确认口径。实现时从同一份配置读取，避免组件、提示词与检查单各写一个数字。

### 6.3 主角参考图提示词（第 2 节）

```text
请先为我的绘本主角生成一张参考图，用来确认长相。
只生成主角，不要生成整页绘本。

角色固定特征：
颜色：<...>
发型/外形：<...>
衣服：<...>
标志物：<...>

画风：<画风>
色调：<色调>

请让角色保持中性姿势、清楚露出上述特征，方便我之后逐页沿用。
```

### 6.4 逐页插画提示词（第 2 节）

每页单独一段，固定包含：页序、画面、动作、情绪、环境、角色特征、画风、不要做什么。

```text
这是绘本第 <n> 页的插画。

画面：<分镜中的画面>
角色动作：<分镜中的动作>
角色情绪：<分镜中的情绪>
环境：<孩子补充>

角色固定特征（每一页都必须一致）：
颜色：<...>
发型/外形：<...>
衣服：<...>
标志物：<...>

画风：<...>
色调：<...>
比例：<...>

不要改变角色长相，不要加入文字，不要新增分镜里没有的主要角色。
```

### 6.5 修改提示词（第 2 节，检查后）

```text
请只修改这一页，不要重做整本绘本，也不要改变角色的固定特征。

要改的地方：<孩子指出的一处>
改成：<孩子描述的目标状态>
必须保留：<画面/动作/情绪/环境/角色特征>

改完后告诉我：你改了哪里，还有哪里需要我自己检查。
```

### 6.6 提示词的可测试约束

实现时用纯函数生成，测试至少覆盖：

1. 故事卡缺项时，分镜提示词必须列出缺失项，而不是编造。
2. 页数固定为 6，且组件、提示词、检查单读取同一份配置。
3. 逐页提示词必须包含四项角色固定特征。
4. 修改提示词必须包含“只修改这一页”和“不要改变角色固定特征”。
5. 任何提示词都不得包含真实姓名、学校、电话、邮箱或住址字段。
6. 孩子选择“跳过”的格子，提示词中明确写“待补充”，不自动补齐。
