## 一、从参考站提炼的原则（只借原则，不借资产）

> 括号内为实测证据。20 站调研的完整计数见 `references/research/2026-10-14-portfolio-sites-20.md` §2.1。

| # | 原则 | 实证依据 |
|---|---|---|
| 1 | **一条强主张 + 一个强调色 + 一个动作** | haoqi 首屏只有一个视觉主角，全站收敛为「米白底 + 纯黑 + 单一荧光绿」。20 站里 12 站是浅色低彩度底 + 仅 1–2 个饱和强调色；`heysai` 只用了**一个**强调色 |
| 2 | **强调色只给最重要的那一下** | haoqi 的荧光绿只出现在手绘签名描边上；hiesther 的黄只用于贴纸与强调词 |
| 3 | **层级靠极端的字号跳跃，不靠字重。** 实测展示字与正文比约 **7–10×**，且大标题常用 **weight 400–500** | `dino` 148px、`oiloil` 140px、`majd` 120px、`hontran` 118.7px、`lixiaolai` 89.6px 对 16px 正文；`lixiaolai` 与 `ricardo` 的主标都设为 **weight 400** |
| 4 | **动效 = 一次入场 + 若干微型小动作**，不做重场景。**越克制的站越自信** | 最轻的站只有 **0–4 个**动画（`g-dea` 0、`aaabad`/`dino` 3、`brober` 4）；最重的同时页长 10.5k–15.5k px、带 4–6 个 canvas。haoqi 无 WebGL、全站零 `<img>` |
| 5 | **减动效 = 直接给最终态**，不是变慢 | haoqi 实测：`prefers-reduced-motion` 下无限旋转整个关掉、SVG 描边直接 `stroke-dashoffset: 0; opacity: 1`。⚠️ 20 站里**只有 5 站**真的写了 `prefers-reduced-motion` —— 这在本项目是差异化优势，不是及格线 |
| 6 | **元信息条 = 廉价而高辨识的记忆点** | haoqi 底栏时钟 / `GMT+8` / 坐标 `0597 X 0379 Y`；`mantis` 的实时纽约钟；`g-dea` 的 `☕🌜 22:34 14.10.2026` |
| 7 | **档案式条目胜过轮播**；空状态要显式说明 | haoqi 项目行 = `类型 + 名称 + 年份`；`dino` 是**日期开头、纯文字、零图片**的项目索引（14 行）；`hiesther` 直接写「更多作品整理中 →」，`akkila` 写 `3 of 12 visible` + `[view all]` |
| 8 | **编号 = 可扫读的导航骨架**（7/20 站用） | `§ 01 ARTICLES / § 02 BOOKS`、`01 The Craft → 07 Contact`、`02FEATURED WORK`、`⟪ 01 // 05 ⟫`。让上万像素的长页变得可导航 |
| 9 | **自述式可信度胜过奖项墙**（7/20 站用） | 自报排版（`SET IN Newsreader, NOTO SERIF & INTER`）、诚实的量（`~2 articles / week`、`replies in < 24h`、`3 of 12 visible`）、状态徽标（`AVAILABLE · open to roles`）。这些**可核对的小细节**比奖杯更能回答家长的真实问题 |
| 10 | **中英配对是第一等的排版手法**（6/20 站，其中 4 站是中日韩 ↔ 拉丁） | `nudot` 的 `WEBDESIGN（ 網頁設計 ）` 与全角括号副标题 `（ 專注本質的數位實踐 ）`；`oiloil` 的 `中 \| EN`；`lixiaolai` 的 `中文 · English` 双 RSS。**这是本清单里对 MakerX 最可直接复用的排版想法** |
| 11 | **用「覆盖在文字上的实物」做出漂浮感，一张图就够** | `oiloil`：140px 巨标 + 一张 331×441 的实物图片压在字上，**零 canvas**。`majd`：120px 标题 + **三个不同尺度的漂浮物体**（124×124 / 220×251 / 173×173）+ 一个 58px 的巨大数字，同样零 WebGL |

**同时明确不采用**（这些是参考站的**独特视觉作品**，照搬即侵权）：
- ❌ haoqi 的米白 + 荧光绿配色与手绘签名描边
- ❌ hiesther 的「桌面 OS + 终端窗口 + 散落文件图标」整体隐喻与 Cola 导览角色
- ❌ `g-dea` 的位图桌面 + 图标网格、`oiloil` 的 `Oil®` 抽象单词品牌体系、`nudot` 的括号排版具体版式
- ❌ 任何参考站的字体文件、插画、图标、文案

**反面教材（实测，教育场景不可接受）**：haoqi 全站没有 `<h1>`/`<h2>`、`user-scalable=no` 禁止缩放；`heysai` 的正文 DOM 文字实际是 `I I build build software software…`（逐词动画把每个词复制了一遍，读起来翻倍）；`hontran` 的 `h1` 真实内容是 36 行单字符堆叠；`g-dea` 整页是一张位图、**且对手机说「Go back to portrait mode」**。本项目这几条全部反着做。

## 二、视觉概念：造物实验舱

一句话：**一块浅蓝色的工作台，上面是一组深墨重字 + 一个发着青蓝光的造物物件，四周是像真在运转的实验数据。**

### 2.1 首屏主视觉 = 用户已提供的素材（首选）

**用户于 2026-10-15 提供了首屏视觉参考**：`references/MakerX AI造物实验室.png`。它现在是首屏主视觉的**首选参考**；页面可以围绕它优化构图和动效，不再需要先自绘「造物装置 X」。

![首屏主视觉（用户提供）](../references/MakerX%20AI造物实验室.png)

> 当前文件由 `ffprobe` 识别为 PNG `rgb24`，不要把旧版本的透明度统计当作当前素材事实。页面背景与图片先按独立图层设计，最终构图以浏览器中的实际效果为准。

实测属性（细节见 [实测记录](../references/research/2026-10-15-hero-image-measurement.md)）：

| 项 | 值 | 对设计的含义 |
|---|---|---|
| 尺寸 / 比例 | **1774 × 887**，**2:1** | 标准横幅比例，适合桌面首屏主视觉带；移动端需单独排版 |
| 像素格式 | **rgb24** | 当前文件没有可依赖的 alpha 通道；页面背景仍由 CSS 负责 |
| 深墨色 | `#111315`（设计令牌） | 作为页面正文和主按钮的可读深色；最终像素比例以当前文件和浏览器效果为准 |
| 长春花蓝 | `#7BA4F0`（设计令牌） | 作为装饰 / 发光同族色，不作为正文色 |
| 青色 | `#77DAF8`（设计令牌） | 作为装饰 / 发光 / 高光色，不作为正文色 |
| 构图 | 当前页面把整张图作为一个视觉单元使用 | 不在页面层面再拆成左右栏；可围绕完整图片优化留白和动效 |
| 可确认文字 | 以用户确认的图稿和页面实际渲染为准 | 未经视觉确认的图内文字不做额外推断 |

> ⚠️ 我**没有看过这张图**（视觉模型不可用）。上表是像素统计，不是观感。它的字体、描边、材质、右侧物件的具体形态、以及是否还有我没识别出的文字，**都未经确认**。若需据此微调排版，请以你的肉眼判断为准，并告诉我结论。

### 2.2 三个构成要素

1. **实验舱（外壳，自绘）** — 极浅冰蓝底色 `#E9F2FD` + 极淡工程网格底纹 + 发丝分隔线。页面像一块干净的实验台面。
2. **首屏主视觉参考（用户素材）** — 以用户提供的图形和品牌字为起点，页面可以优化整体构图和动效；不覆盖原文件。
3. **实验元数据（气质，自绘）** — 等宽字体的小字数据条：`project archive`、`continuously building`、`9–12`。这是「一个持续运转的实验室」而非「一个宣传页」的关键。

### 2.3 与任务书的一处偏差（已解决）

任务书写「参考 haoqi.design 的轻盈浅蓝色背景」，但实测 haoqi.design 的底色是米白 `rgb(251,250,244)`、强调色是荧光绿 `#C0FE04`，**不是浅蓝**。本方案按任务书的**文字意图**走**冰蓝**路线，没有照抄 haoqi 的实际配色 —— 而且这一点现在有了更强的依据：**用户提供的首屏图主色是近黑深墨，它要求浅色底**（见 `docs/decisions.md` C-01）。

## 三、色彩系统

### 3.1 令牌

**品牌前景色直接取自用户提供的首屏图**（这是最高依据，不得改动素材本身的颜色）：

| 令牌 | 值 | 用途 | 实测对比度 |
|---|---|---|---|
| `--brand-ink` | `#111315` | 品牌深墨（= 首屏图主色，也用于正文与标题） | 冰蓝底 16.48:1 ✅ / 白底 18.62:1 ✅ |
| `--brand-cyan` | `#77DAF8` | **装饰专用**：发光、高光、图形填充 | ⚠️ 浅底仅 1.41:1，**禁止用于文字** |
| `--brand-peri` | `#7BA4F0` | **装饰专用**：物件、图形填充 | ⚠️ 浅底仅 2.21:1，**禁止用于文字** |

**页面与界面令牌**：

| 令牌 | 值 | 用途 | 实测对比度 |
|---|---|---|---|
| `--lab-sky` | `#E9F2FD` | 页面主底色（冰蓝白） | 与 ink 16.48:1 |
| `--lab-surface` | `#FFFFFF` | 卡片 / 面板底 | 与 ink 18.62:1 |
| `--lab-deep` | `#DCEBFF` | 凹陷区 / 次级面板 | 与 ink 15.40:1 |
| `--ink` | `#111315` | 正文与标题 | — |
| `--ink-muted` | `#4A5568` | 次级文字、说明 | 6.66:1 ✅ AA |
| `--ink-soft` | `#5A6478` | 三级文字、元信息 | 5.27:1 ✅ AA |
| `--line` | `rgba(17,19,21,0.14)` | 发丝分隔线（网格感） | 装饰 |
| `--line-strong` | `rgba(17,19,21,0.32)` | 强调边框、hover | 装饰 |
| `--accent-wire` | `#2F4BC7` 长春花蓝（深色同族） | **交互色**：链接、焦点环、进行中状态、当前步骤 | 冰蓝底 6.30:1 ✅ / 白底 7.11:1 ✅ |
| `--accent-cta` | `#111315` 品牌深墨 | **主按钮底色**（白字） | 18.62:1 ✅ |
| `--accent-warn` | `#FF6B4A` 珊瑚橙 | 仅用于「注意 / 边界」提示（如「今天先不做」） | ink on it 6.61:1 ✅ |
| `--cyan-text` | `#0E7490` 深青 | 需要「青色语义」的文字（青色的可读同族色） | 冰蓝底 4.74:1 ✅ |
| `--prompt-bg` | `#111315` | **提示词代码块底**（全站唯一深色块） | 亮字 18.62:1 ✅ |
| `--accent-maker` | `#FFC53D` 造物黄 | ⏳ **待决定（D-01）**：默认**不再用于 CTA** | ink on it 11.80:1 ✅ |

**用色纪律**
- **主按钮只有一种颜色：品牌深墨 `#111315` + 白字。** 这样 CTA 与首屏图的重字同源，不会引入第三个色相。
- **青色与长春花蓝原色只做装饰**（发光、图形、高光、进度条的填充）。需要它们"说话"时，用 `--accent-wire` 或 `--cyan-text`。
- 一屏之内 `--accent-wire` 用于交互态，`--accent-warn` 只用于边界提示。
- **不做渐变彩虹、不做发光霓虹、不做玻璃拟态。** 唯一允许的"发光"来自首屏图本身。

### 3.2 为什么这样配色（以及与原方案的差异）

原方案是「造物黄 `#FFC53D` + 电光紫 `#5B3DF5`」。用户提供首屏图后，**色彩身份由素材决定**，因此做了三处收敛：

| 原方案 | 现方案 | 原因 |
|---|---|---|
| 正文色 `#0A1020` | **`#111315`** | 与首屏图主色完全一致，页面文字和首屏字是同一个颜色（`docs/decisions.md` C-03） |
| 链接/焦点 `#5B3DF5` 电光紫 | **`#2F4BC7`** 长春花蓝深色同族 | 与首屏图的长春花蓝 `#7BA4F0` 同色相、更深，可读性更好（冰蓝底 6.30:1，原电光紫为 5.42:1），且不引入新色相（C-02） |
| CTA 造物黄 | **`#111315` 深墨实心按钮** | 避免第三个色相与首屏图争夺注意力（C-02 连带） |

`--accent-wire = #2F4BC7` 是 `--brand-peri = #7BA4F0` 的**深色同族**，两者色相一致、明度不同：前者用来写字，后者用来发光。这样"蓝"在站内是一个家族，而不是两个不相干的颜色。

### 3.3 验证要求（Phase 3 必查）

- 所有正文 ≥ 4.5:1，大字（≥ 24px 或 ≥ 18.66px 粗体）≥ 3:1。上表已预检，**落地后需用工具复测实际渲染**。
- 焦点环：`2px solid var(--accent-wire)` + `outline-offset: 2px`，任何情况下不可移除。
- 不实现浅色/深色主题切换（不在 MVP 范围）；但令牌化写法保证以后可加。

### 3.4 标签色令牌（chip tokens）

借鉴 `dino-kupinic.dev` 的做法：把「主题/能力」做成一套**成令牌、可复用**的柔和色片，同一个概念在项目卡、步骤、验收表里都用同一个颜色。这样孩子能靠颜色认出「这属于哪一类」，而且**新增实验时不用重新调色**。

| 令牌 | 底色 | 文字色 | 对比度 | 用途示例 |
|---|---|---|---|---|
| `--chip-hardware` | `#DCE9FF` | `#123A78` | 9.01:1 ✅ | 硬件 / 设备 / 工具 |
| `--chip-material` | `#FFE6D5` | `#7A3A12` | 7.18:1 ✅ | 材料 / 手工 / 图纸 |
| `--chip-code` | `#DDF3E4` | `#14512C` | 8.03:1 ✅ | 代码 / 逻辑 / 提示词 |
| `--chip-design` | `#E9E2FF` | `#3B2A80` | 9.18:1 ✅ | 设计 / 视觉 / 风格 |
| `--chip-voice` | `#FFF0C2` | `#6B4A00` | 7.10:1 ✅ | 表达 / 路演 / 展示 |

**状态徽标**（由内容模型 `status` 驱动，颜色 + **文字**双重编码，不靠颜色单独传达）：

| 状态 | 底色 | 文字色 | 对比度 | 展示 |
|---|---|---|---|---|
| `open` | `#D6F5DF` | `#0F5132` | 8.02:1 ✅ | 开放中 |
| `developing` | `#E7E9EE` | `#404A5C` | 7.35:1 ✅ | 研发中 |
| `planned` | `#EDE9F7` | `#46406B` | 7.98:1 ✅ | 即将开放 |

> 色片底色与页面底色 `#E9F2FD` 的对比约 1.03–1.08:1，属于**同色系内的柔和分层**，因此色片必须有 1px 边框（`--line`）才在浅底上立得住。**色片永远不承担唯一的语义**，旁边一定配文字。
>
> 说明：标签色是一套**独立的语义分类色**（用来区分「这属于哪一类」），与品牌交互色 `--accent-wire` 的职责不同，**不要求同色相**。它们的共同要求只有一条：文字对比度 ≥ 4.5:1。

## 四、字体系统

### 4.1 选择（并说明**不**选什么）

```css
--font-sans: system-ui, -apple-system, "Segoe UI", "PingFang SC",
             "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans SC",
             Roboto, "Helvetica Neue", Arial, sans-serif;
--font-mono: ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas,
             "Liberation Mono", "Courier New", monospace;
```

- **中文字体不下载 webfont**。中文 webfont 动辄 3–8MB，与「加载快」直接冲突；系统字体栈在 Windows（微软雅黑）、macOS（苹方）、Android（Noto Sans SC）上都能得到清晰的中文渲染。
- **不用参考站的字体**。haoqi.design 用的是第三方品牌可变字体 `tiktok`（实测 `document.fonts` 为 `tiktok:100 900:loaded`），字体文件有授权限制，**不复制、不引用**。
- **拉丁文与数字（可选加分项）**：若 Phase 1 原型觉得系统拉丁字重不够「大标题的力度」，再自托管 **Inter**（SIL OFL，可商用）的 **latin 子集**（约 100KB woff2），只用于标题与数字，`font-display: swap`。这是**待定项**，默认不做，避免无谓依赖。
- **等宽字体承担气质**：所有元数据、编号、时长、坐标、提示词正文一律用 `--font-mono`。这是「实验室 / 工程感」最便宜也最有效的来源（参考站用 HUD 顶底栏达成同样效果）。

### 4.2 字号阶梯（`clamp()` 流体排版）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--fs-display` | `clamp(2.75rem, 8vw, 7rem)` | 首屏主张（大标题） |
| `--fs-h1` | `clamp(2rem, 4.5vw, 3.25rem)` | 页面主标题（实验 001 项目名） |
| `--fs-h2` | `clamp(1.5rem, 3vw, 2rem)` | 区块标题 |
| `--fs-h3` | `1.125rem` | 卡片标题 / 小节标题 |
| `--fs-body` | `1rem`（行高 1.7） | 正文 |
| `--fs-meta` | `0.8125rem`（等宽，字距 `.02em`） | 元数据、编号、徽标 |
| `--fs-prompt` | `0.9375rem`（等宽，行高 1.75） | 提示词正文 |

- **层级靠字号跳跃，不靠字重**（实测 20 站里展示字与正文比约 7–10×）：`--fs-display` 最大 112px 对 `--fs-body` 16px = **7×**，落在实测区间内。**不要把字号和字重同时拉满。**
- 首屏主张字重 `700`；若要更「邀请式」的观感，可降到 `600`（参考站 `lixiaolai` / `ricardo` 的大标只用了 `400`，读起来是「邀请」而非「喊」）。区块标题 `700`，卡片标题 `600`，正文 `400`。
- **中文标题不用 `900`**：部分安卓机型的 CJK 合成粗体会发虚，`700–800` 更稳。中文字形笔画密，大字重 + 大字号叠加会糊成一团。
- `--fs-meta` 用 `600` + 字距 `.02em`，做出「仪表读数」感。
- **行宽**：正文最大 `68ch`（约 34 个汉字），提示词块最大 `80ch`。
- **不做逐词/逐行揭示**（实测反面案例：`heysai` 的正文 DOM 真的变成 `I I build build software software`，阅读量翻倍、读屏与复制粘贴全坏）。

### 4.3 中英混排

- 标题允许中英混排，英文用 `--font-sans` 的拉丁部分（或未来的 Inter），数字一律走 `--font-mono` 以强化「实验编号」的档案感。
- 英文与中文之间保留 0.25em 的视觉间隙（用 `letter-spacing` 或显式空格），避免拥挤。

### 4.4 两个要主动采用的排版手法

**① 中英配对（`WEBDESIGN（ 网页设计 ）` 式）**
实测 20 站中有 6 站把双语配对当作一等排版手法，其中 4 站是中日韩 ↔ 拉丁。对 MakerX 它解决一个真实问题：**孩子读中文，家长认得出英文术语，两者互不当作对方的翻译。**

用法：在能力标签、区块标题、元数据处使用。例：

```
需求表达（Requirement）
提示词结构（Prompt）
输出判断（Judge the Output）
测试与迭代（Test & Iterate）
```

规则：中文用 `--font-sans`，拉丁部分用 `--font-mono` 或字重略低 + `--ink-soft` 色，全角括号紧跟中文不换行（`white-space: nowrap` 包住整个配对）。**不做语言切换开关**（MVP 范围外，且家长页与孩子页是同一页的两段，不是两个语言）。

**② 编号骨架**
所有长区块用编号前缀，让页面可扫读、也让「这是一套有结构的课程」这件事自己说话。**项目编号就是它的天然编号**：

```
实验编号 001 ｜ AI星球
  01 项目任务
  02 学习目标
  03 课前准备
  04 实验步骤
  05 提示词工具箱
  06 素材与下载
  07 验收标准
  08 路演指南
  09 作品集出口
```

（与 `docs/site-map.md` §三 的区块顺序一一对应；面包屑与「上一实验 / 下一实验」属于页面框架，不参与编号。）

编号用 `--font-mono`，`--ink-soft` 色，字号 `--fs-meta`；编号不参与标题的语义（放在 `<a>` 的锚点里，标题本身仍是干净的 `<h2>`）。

## 五、首屏主视觉的实现规格

### 5.1 首选：使用用户提供的素材（`MakerX AI造物实验室.png`）

**这是当前方案。** 不重绘、不改色、不重新构图。

| 项 | 规格 |
|---|---|
| 源文件 | `references/MakerX AI造物实验室.png`（1774×887） |
| 实施位置 | Phase 1 起复制到 `src/assets/hero/`（Astro 会做尺寸与格式优化），**源文件保留在 `references/`** |
| 输出格式 | 优先 `AVIF` / `WebP`，`PNG` 作为兜底；输出宽度档位 `640 / 960 / 1280 / 1774`，`sizes` 按实际栅格给 |
| 背景 | 由页面 CSS 负责；当前 PNG 为 `rgb24`，不把透明叠加作为前提 |
| 尺寸策略 | 桌面占首屏视觉主导（约 55–65% 宽）；窄屏按比例缩小并**移到文字下方**（见 §七） |
| 动效 | **只对容器做轻微漂浮**（`transform: translate3d` ≤ 8px，8–12s），**不对图片内部元素做任何处理**（它是位图，内部元素动不了） |
| 无障碍 | `alt` 必须写实质描述；若图片只是装饰则 `alt=""` 并 `aria-hidden="true"`。**⚠️ 因为我没看过这张图，`alt` 文案需要你给出** |

**为什么不能自己改它的颜色**：图中深墨 `#111315` 是品牌字色，青 `#77DAF8` 与长春花蓝 `#7BA4F0` 是物件的发光色。任何调色都会破坏它与页面令牌的同源关系（§3.2 的色彩家族正是从它推出来的）。

### 5.2 自绘装置（备选，仅当素材无法使用或需要补充装饰时）

若首屏图最终不用，或需要在其他页面补充同族装饰，可按下面方式自绘。**合用色已换成品牌色**：

分 6 层，从后到前：
1. `glow` — 极淡的 `--brand-peri` 径向渐变（`opacity: .18`），给装置打光
2. `shadow` — 模糊椭圆软阴影（`feGaussianBlur`）
3. `body-back` — 背面笔画（半透明，`fill: rgba(17,19,21,.08)`）
4. `body-front` — 正面笔画：主填充 `rgba(255,255,255,.72)` + 内高光（`linearGradient` 白→透明）+ 1.5px 描边 `rgba(17,19,21,.24)`
5. `highlight` — 沿边缘的高光弧线（可用 `--brand-cyan`）
6. `glyphs` — 环绕 5–6 个自绘工具符号：**星星 ✦、光标箭头、线框立方体、拼装块、代码括号 `{ }`、旋钮**。尺寸 16–40px，各自独立漂浮

**漂浮方式**：`transform: translate3d()` + 不同 `animation-duration`（6s–14s，取互质时长避免同步）与 `animation-delay` 错开。**只动 `transform` 与 `opacity`**，不动 `top/left`。

**衬托手法**：装置后面放极淡的工程网格（`background-image: linear-gradient` 交叉线，`opacity: .35`）与 1–2 个「标注引线」（细线 + 小圆点 + 等宽小字，如 `X-AXIS`、`v1.0`），把主视觉变成一张实验图纸。

**禁用**：不生成写实 3D 模型文件、不使用在线 3D 素材、不使用 emoji 作为主视觉元素。

**成本已实测过的替代路线**：
- `oiloil.org` 只用**一张 331×441 的实物图片压在 140px 大字上**就做出「东西浮在文字上」的效果，**零 canvas**。
- `majd-portfolio` 用**三张不同尺度的普通图片浮在标题周围**（124×124 / 220×251 / 173×173）+ 一个 58px 巨大数字作为配重，同样零 WebGL。
- 结论：**不要因为「想做立体感」而升级到 Three.js。**

## 六、动效系统

### 6.1 动作清单（全部可关）

| 动作 | 触发 | 时长 / 缓动 | 说明 |
|---|---|---|---|
| 首屏入场 | 页面加载 | 700ms / `cubic-bezier(.22,1,.36,1)`，元素间错峰 60–90ms | 主视觉 → 标题 → 主张 → CTA 依次落位。**总耗时 ≤ 1.2s** |
| 主视觉漂浮 | 持续 | 8–12s / `ease-in-out`，无限 | **只对首屏图的外层容器**做位移 ≤ 8px。图片内部是位图，不能也不应做元素级动画 |
| 符号微浮 | 持续 | 各自 7–13s | 位移 ≤ 8px，错峰。**仅用于自绘装饰符号**，首屏图内没有可动元素 |
| 滚动揭示 | 进入视口（`IntersectionObserver`） | 400ms / 同上 | 位移 `16px` + 透明度，**只对区块用，不对每行文字用** |
| 卡片悬停 | hover / focus | 180ms | 上移 `4px` + 边框转实 + 阴影加深；同时给出等价的 `:focus-visible` 样式 |
| 元数据滚动 | 滚动 | — | 首屏底部的实验数据条可轻微反向位移（≤ 20px），非必需，若影响性能则去掉 |
| 复制反馈 | 点击复制 | 200ms | 按钮文案短暂变「已复制 ✓」；**不靠动画传达状态**，用文字 |
| 焦点 | Tab | 即时 | 2px `--accent-wire` 焦点环，无过渡延迟 |

**动效预算**：单页同时运行的动画元素 ≤ 8 个；所有无限循环动画只用 `transform` / `opacity`。

### 6.2 减动效（硬要求）

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .001ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .001ms !important;
    scroll-behavior: auto !important;
  }
  .float, .reveal { transform: none !important; opacity: 1 !important; }
}
```

原则（照搬参考站实测的正确做法）：**不是把动画变慢，而是让元素直接处于「最终已完成」状态** —— 该出现的都出现、该描边的已描完。内容在减动效模式下**不减少任何信息**。

另需：
- 首屏内容即使 JS 未执行也必须可见（入场动画的初始隐藏状态**只能由 JS 添加 class 后才生效**，即「渐进增强」，禁止在 CSS 里默认 `opacity: 0`）。
- 提供 `prefers-reduced-motion` 之外的第二重保险：如果 `IntersectionObserver` 不可用，直接显示全部内容。

## 七、移动端与降级策略

| 断点 | 布局 |
|---|---|
| `≥ 1024px` | 两栏：文字左，首屏图右（占约 55–65% 宽）；流程横向 5 节点；元数据条横排 |
| `768–1023px` | 首屏图缩到约 60% 宽并**移到文字下方**（保持 2:1 比例，不裁切）；流程横向但节点变小 |
| `< 768px` | 单列；首屏图缩到约 45% 宽、置于文字下方；流程纵向；锚点条横向滚动 |

具体规则：
- **首屏图在窄屏上会变得很矮**（2:1 比例，宽度 45% 时高度极小）。因此**移动端必须把它的字号信息用真实 HTML 文本重新表达一遍**（品牌名 + 主张），不能让它成为唯一的品牌信息来源 —— 否则小屏上品牌名只有几十像素高。（⚠️ 由于我无法看图，字在图中 vs 图中的字是图形，这一点需你在原型上确认。）
- **触控目标** ≥ 44×44px（勾选框、复制按钮、导航项）。
- **不做光标跟随效果**（触屏无光标，且属于「为动效而动效」）。
- **不做横向溢出**：长提示词用 `<pre>` + `overflow-x: auto` + `-webkit-overflow-scrolling: touch`，不撑破页面。
- **移动端不减信息**，只减装饰：自绘装饰符号从 6 个减到 2 个，视差取消，阴影简化。
- **打印**：步骤区与验收表可打印；隐藏导航、装饰、首屏图（省墨）；提示词块改为白底黑字。
- **无 JS**：内容完整可读；复制按钮降级为「手动选中」提示；步骤勾选状态丢失可接受。

## 八、背景方案（已由首屏图收敛为一个答案）

首屏图的主色是近黑深墨 `#111315`（占 7.6%），实测：

| 底色候选 | 深墨在其上的对比度 | 结论 |
|---|---|---|
| `#E9F2FD` 冰蓝 | **16.48:1** | ✅ 可读 |
| `#FFFFFF` 白 | **18.62:1** | ✅ 可读 |
| 深色 `#0B0F14` | **1.03:1** | ❌ **等于看不见** |

**结论：底色必须是浅色。** 深色首屏方案（方案 B 的深色变体、或任何"深底 + 霓虹发光"的 AI 作品集套路）**会让这张图的主视觉完全消失**，无论它单独看有多好看。

因此原「方案 A / B / C 三选一」不再需要：**底色定为 `#E9F2FD` 冰蓝**（它既符合任务书「轻盈浅蓝」的文字意图，又与首屏图的青蓝物件同色系）。原方案 B（米白 + 荧光绿）与方案 C（练习本）作废，原因分别是「与 haoqi.design 撞脸」和「滑向低幼卡通」。

## 九、组件视觉规格（Phase 1 原型要验证的部分）

**ProjectCard（项目卡）**
- 白底面板、1px `--line` 边框、圆角 16px、内边距 24px；无渐变、无彩色阴影。
- 字段顺序（来自 8/20 站反复出现的「可比元数据」结构：**序号 → 缩略 → 标题 → 1–2 个标签 → 时长/日期 → 一句产出**，本项目按此改写）：

  | 位置 | 内容 | 字体 |
  |---|---|---|
  | 左上 | `实验编号 001` | `--font-mono`, `--fs-meta` |
  | 右上 | 状态徽标（开放中 / 研发中 / 即将开放） | 色片 + 文字 |
  | 主体 | **AI星球** | `--fs-h3` 或更大，`600` |
  | 主体 | 用 AI 把一个想法变成可打开、可继续改进的个人网页。 | `--fs-body` |
  | 底部 | 标签：`2 课时 × 90 分钟`、`9–12 岁`、`每班 5 人` | chip 或 `--font-mono` |
  | 右下 | 箭头 `→` + 「进入实验」 | — |

- 悬停/聚焦：上移 4px、边框转 `--line-strong`、装置剪影微抬起。`:focus-visible` 给出同样明显的变化。
- **可点击性跟随 `pageState`，状态徽标跟随 `status`**（两者是不同的字段，见 `docs/decisions.md` C-08 / C-09）：
  - `pageState: "live"` → 显示箭头 `→`，整卡可点（`<a>` 包整卡，`<a>` 内不再套 `<a>`）。
  - `pageState: "coming-soon"` → **虚线**边框、降饱和、**不显示箭头**、整卡不可点（渲染为 `<div>` 而非 `<a>`），并把「即将开放」写在最显眼处。
  - `status: "developing"` 但 `pageState: "live"` 时**仍可点击**（页面已实现），徽标显示「研发中」以如实说明课程就绪度。
- **不做缩略图占位假图**：暂时没有真实封面就不放图（`dino` 的纯文字项目索引证明没有图片也能成立）。

**CTA（行动按钮）**
- **一个页面只有一个主按钮。** 首屏主按钮 = 「开始实验 001」，样式为 `--accent-cta` 深墨实心 + 白字（18.62:1）+ 圆角 999px 或 12px。
- 次行动一律降为**文字链接**（`--accent-wire` + 下划线），不出现第二个实心按钮。首屏的「先看看怎么上课」按此处理（`docs/decisions.md` C-07）。
- 触控目标 ≥ 44×44px；`:focus-visible` 为 `2px solid var(--accent-wire)` + `outline-offset: 2px`。
- 不存在「报名 / 登录 / 购买」按钮（第一版没有这些功能）。

**PromptBox（提示词卡）**
- 全站唯一深色块：底 `#111315`、亮字、等宽、圆角 12px。
- 右上角复制按钮；正文可横向滚动；上方一行等宽标签写「什么场景用」。
- 目的：让孩子一眼认出「这一段是要复制的」，与正文形成明确的功能区分。

**StepList（实验步骤）**
- 左列大号等宽序号（`01`–`08`），右列内容；每步带「产出」小标签与可选勾选框。
- 当前步骤用 `--accent-wire` 左侧色条标记（**不靠颜色单独传达**，同时加「进行中」文字）。

**RubricTable（验收标准）**
- 桌面为表格；移动端转卡片。三档：`起步`（灰）、`不错`（长春花蓝浅底）、`很棒`（深青浅底），文字对比度按 §3.1 校验。

**MetaStrip（实验元数据条）**
- 等宽小字，`·` 分隔，`--ink-soft` 色；出现在首屏底部与项目页头部。这是记忆点，务必保留。
- 内容示例：`实验编号 001` · `AI星球` · `9–12 岁` · **`研发中`**（状态来自 `status` 字段；课堂提示词工具已可进入）
- **可加一条「自述式」的诚实状态**（7/20 站用这招建立可信度，比奖项墙有效）：例如 `本期 1 个实验开发中 · 2 个在计划`、`物料 2 份待补充`。
- ⚠️ **这类数字必须是真的、由内容数据生成**，不能写死、不能编。宁可显示「待补充」也不要有好看的假数字。**`updated` 字段缺失时不显示任何日期，而不是显示「待确认」**（`docs/decisions.md` C-06）。

## 十、反模式清单（明确不做，附实测依据）

| 反模式 | 实测依据 |
|---|---|
| ❌ **首屏铺满 WebGL / canvas** | `mantis` 在 y=0 放 1280×800 canvas；`thestart` 叠了两个满屏 canvas；`justinesoulie` 首屏**唯一**内容就是一张 1268×632 canvas；`hontran` 5 个、`nudot` 4 个 canvas + 10 个视频。教室里的旧平板只会得到一个空白方块 |
| ❌ **加载进度条 / 入场闸门** | `redoyan` 的 `LOADING 0%`、`thinh` 的 `01…50` 计数器、`heysai` 的 `CALIBRATING 99%`、`hiesther` 的 `Press Enter to Launch`。孩子看到 0% 只会以为坏了；计数器是网络可以随时打破的承诺。**本项目不做任何内容闸门，包括「Press Enter」** |
| ❌ **劫持滚动（smooth-scroll 库）** | `lenis` 出现在约 7 个站点上。它破坏触控板惯性、键盘翻页、`Ctrl+F` 与滚动条预期，在共享设备上表现为「页面滚不动」 |
| ❌ **自定义光标 / 光标跟随** | `erenaygun`、`justinesoulie`、`nudot` 都覆盖了 `cursor:`。9–12 岁大多在触屏上，光标效果根本不存在；混合设备上还会挡住孩子需要的指针 |
| ❌ **逐词 / 逐行揭示正文** | `heysai` 的 DOM 正文实际是 `I I build build software software…`——逐词动画把每个词复制了一遍。**这是本次调研里最清楚的动效伤害阅读的案例** |
| ❌ **竖排单字堆叠标题** | `hontran` 的 `h1` 真实内容是 36 行单字符。9 岁孩子读不了，读屏、搜索、复制全坏 |
